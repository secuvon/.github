# Security policy

Secuvon tests AI agents for security weaknesses. This policy explains how to
report a vulnerability in Secuvon itself.

## Reporting a vulnerability

Email **[security@secuvon.ai](mailto:security@secuvon.ai)**. Please do not
open a public GitHub issue.

Our machine-readable security contact is
[secuvon.ai/.well-known/security.txt](https://secuvon.ai/.well-known/security.txt).

Please include:

- what you found and where, for example secuvon.ai, api.secuvon.ai or a report
  download
- the steps to reproduce it
- the impact you believe it has
- any proof of concept, screenshots or logs
- how we can reach you

We do not publish an encryption key yet. If your report contains sensitive
data, say so in a first short email and we will agree a secure way to receive
the details.

## What happens next

- We acknowledge every report within 3 business days.
- We tell you whether we can reproduce the issue and how we rate its severity,
  and we keep you updated until it is fixed.
- We fix the most serious issues first, and once a fix is live we agree a
  disclosure date with you.

We are a small team, so these are commitments we can keep. If something takes
longer, we will tell you.

## Please do not

- access, change or delete data that belongs to someone else
- run denial-of-service or load tests against our services
- use social engineering against our team or our users
- disclose the issue publicly before we have had a reasonable chance to fix it

## Scope

In scope: the Secuvon web application at secuvon.ai and its API at
api.secuvon.ai.

Out of scope: third-party services we use (please report those to the vendor),
findings that need an already compromised device or account, and automated
scanner output without a demonstrated impact.

## Recognition

We do not run a paid bug bounty. With your permission, we will thank you by
name when we publish the fix.
